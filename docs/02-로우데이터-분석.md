## 0. ⚠️ 먼저 — 웹 로우데이터 파일은 열리지 않습니다

`전체고객상품(202608191721).xls` 는 엑셀 파일이 아니라 **DRM 문서보안으로 암호화된 파일**입니다.

```
파일 헤더: "BMS DocuRay" ...  (문서보안 솔루션 컨테이너)
```

일반 엑셀/파이썬으로는 열 수 없습니다. 사내 DRM 클라이언트가 깔린 PC에서만 열립니다.

**대신** `결합접수_검수.xlsm` 의 `웹` 시트에 **웹 로우데이터 280행이 그대로 붙어 있어서**,
그걸로 분석했습니다. 구조는 동일합니다.

> 📌 **다음에 자료 주실 때**: 웹에서 받은 xls를 한 번 열어서 **"다른 이름으로 저장 → .xlsx"** 로
> 다시 저장해서 주시면 DRM이 풀린 상태로 넘어옵니다. 그래야 실제 컬럼 순서를 100% 확정할 수 있습니다.

### ⚠️ 1-4. 함정 — `결합` 이라는 글자만 찾으면 오탐납니다

실제 데이터에서 발견한 **가짜 양성** 패턴:

| 패턴 | 실제 예시 | 왜 오탐인가 |
|---|---|---|
| 서식지 **라벨** | `□월요금/모바일 결합 할인금액: 23.100` | 값이 아니라 **항목 이름**. 결합 안 해도 항상 있음 |
| 요금 비교 | `요금 : 결합전 30,800원 / 결합 후 25,300원` | 단순 요금 안내 |
| 부정 문구 | `따로살아도가족 결합불가안내완★` | **결합 불가** |
| 명시적 X | `ㅁ 결합 : X`, `□결합: X` | 결합 없음 |

→ 반드시 **`결합:` 필드값을 파싱**하고, `X`/`없음`/`불가` 는 제외해야 합니다.

### 1-5. 오탈자도 있습니다
`머바일결합19800원` (r98, 모바일→**머**바일) — 고객명 태그가 `변재오/모` 라서 그걸로 잡힙니다.
**BA 텍스트 + 고객명 태그 둘 다 봐야 하는 이유**입니다.

### 🔴 중요 — 원스톱 파일의 서비스번호 마스킹 방식이 다릅니다

```
접수리스트 X : z!66251240***   → 앞 8자리 유효
원스톱     H : z!6825***2039   → 앞 4자리 + 뒤 4자리 (가운데 3자리가 가려짐)
```

**기존 매크로의 "앞 8자리" 키가 원스톱에는 안 통합니다.**
원스톱은 **`앞4자리 + 뒤4자리`** 를 별도 키로 만들어야 합니다.
웹 H열은 11자리 전체가 있으니 `앞4 + 뒤4` 조합 생성이 가능합니다.

## 5. KOS 결합 리스트 양식

**구조**: 1~3행 헤더 혼재 / **3행부터 데이터** (샘플 12건)

왼쪽(A~P)은 KOS처리/서식지검증 영역이고, **실제 고객 데이터는 Q부터**입니다.

| 열 | 이름 | 샘플 | 채워짐 |
|---|---|---|---|
| A | 순번 | 1, 2, 3… | ✅ |
| B~P | KOS처리 / 서식지 등록·검증 | | ❌ 전부 빈값 |
| **Q** | **고객명** | `서여*` `심우*` `윤상*` (마스킹) | ✅ |
| **R** | **생년월일** | `740912` `900626` `710809` | ✅ |
| S | 전화번호 | | ❌ 샘플엔 빈값 |
| T~ | 계약번호/청구계정/모델 등 | | ❌ 빈값 |

### 매칭 가능한 키

현재 사용 가능한 건 **생년월일(R) 6자리뿐**입니다. → 매크로가 R만 쓰는 이유입니다.
하지만 **동명이인/동일생년월일 충돌 위험**이 있으므로,
**전화번호(S)나 고객명(Q) 마스킹 앞글자를 같이 받아오면** 훨씬 정확해집니다.

> 📌 실제 KOS에서 내려받을 때 **S(전화번호) 컬럼이 채워져서 나오는지** 확인 부탁드립니다.
> 채워진다면 `생년월일 + 전화앞5자리` 복합키로 바꿔서 충돌을 없앨 수 있습니다.
