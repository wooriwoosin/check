# 03. 개선 방향 — 웹 1차 검수 → KT전산 2차 검수

---

## 1. 왜 나누나

현재는 **전부 KT전산 안에서** 매크로로 돌립니다. 문제는:

- KT전산은 VPN 안이고 문서보안이 걸려서 **디버깅·수정이 사실상 불가능**
- 웹 데이터만 봐도 알 수 있는 오류까지 전산까지 들고 가서 확인 중
- 매크로가 틀려도 (01 문서의 버그들) 안에서 고칠 방법이 없음

그래서:

```
┌───────────────────────────────┐      ┌──────────────────────────────┐
│  1차 : 웹 검수 (HTML, 사외)     │  →   │  2차 : KT전산 검수 (xlsm, VPN) │
│  웹 로우데이터만으로 판정 가능    │      │  전산 데이터가 있어야만 판정 가능 │
│  → 여기서 다 걸러내고            │      │  → 남은 것만 최소한으로         │
│  → 필요한 열만 정리해서 xlsm 생성 │      │                              │
└───────────────────────────────┘      └──────────────────────────────┘
```

**1차에서 만든 xlsm 파일을 KT전산으로 가져가서, 거기서 로우데이터 붙여넣고 2차 매크로만 돌립니다.**
(암호화된 뒤에도 붙여넣기는 되니까 기존 방식 그대로)

---

## 2. 검수 항목 분류

### 🟦 1차 — 웹에서 끝낼 수 있는 것 (전산 불필요)

| # | 항목 | 규칙 | 현재 상태 |
|---|---|---|---|
| W-1 | **단독 결합후보** | 셋트유형 `단독` + (기타(BA)의 `결합:` 필드값 / 결합 키워드 / 고객명 `/모`·`/결`·`/패밀리` 태그) | ❌ 없음 → **신규** ★최우선 |
| W-2 | **패밀리 상품 결합** | 상품옵션에 `패밀리` 포함 → 결합대상 | ❌ 없음 → 신규 |
| W-3 | **개통기한** | 개통기한(P) == 접수일(S)의 익월 말일 | ✅ 매크로02 → **1차로 이동** |
| W-4 | **상부점 ↔ 접점코드** | 접점코드(AB)별 상부점(AA) 매핑 테이블 | ⚠️ 매크로02 (값 2개만 인정 → 6건 오탐) → **매핑 테이블로 교체 후 1차 이동** |
| W-5 | **판매점 접수경로** | 협력점(Q)에 `■`/`□` → 접수경로(AX) == `5.판매점☆` | ✅ 매크로02 → **1차로 이동** |
| W-6 | **OSS 라인 정합** | 고객명에 `/OSS` 태그 ↔ 같은 고객의 `원스톱해지(OSS)` 라인 존재 여부 (양방향) | ❌ 없음 → 신규 |
| W-7 | **상품 매핑 가능성** | 상품옵션이 KT 상품명으로 정규화 안 되는 건 조기 경고 (`TV에센스`, `일반전화` 등) | ❌ 없음 → 신규 |
| W-8 | **필수값 누락** | 주민번호/명의자연락처/주소/납부정보 빈칸 | ❌ 없음 → 신규 |

> **W-3 / W-4 / W-5 는 지금 KT전산 매크로 안에 있는데, 웹 데이터만으로 판정 가능합니다.**
> 전산에서 뺄 수 있는 항목입니다.

### 🟥 2차 — KT전산 데이터가 있어야만 되는 것

| # | 항목 | 필요 자료 | 현재 상태 |
|---|---|---|---|
| K-1 | **접수 존재 / 상품상이** | KOS 접수리스트 (X, AK) | ✅ 매크로01 → 정규화 버그 수정 필요 |
| K-2 | **개통상태 ↔ 진행상태** | KOS 접수리스트 (U) | ✅ 매크로02 → `보류`/`접수대기` 추가 |
| K-3 | **업체명 대조** | KOS 접수리스트 (I) | ✅ 매크로02 |
| K-4 | **결합 O/X (DPS)** | KOS 결합리스트 (R, S) | ✅ 매크로01 → **키를 생년월일+전화로 강화** |
| K-5 | **원스톱 상태 대사** | KOS 원스톱 (H, I, K, L) | ❌ **매크로에 아예 없음** → 신규 |
| K-6 | **웹미존재 접수건** | KOS 접수리스트 전체 | ✅ 매크로01 |

## 3. 1차(웹) 산출물 — KT전산으로 넘길 xlsm

### 3-1. 지금 시트가 67열 통째로 넘어가는데, 2차에 실제로 필요한 열은 12개뿐입니다

| 넘길 열 | 이름 | 2차 어디에 쓰나 |
|---|---|---|
| A | No | 원본 추적 |
| B | 고객명 | 결과 확인 |
| C | 상품명 | K-1 |
| D | 상품옵션 | K-1 (상품 비교) |
| **+** | **상품정규화값** | K-1 — **1차에서 미리 계산해서 넣어줌** |
| G | 셋트유형 | K-4 (DPS만 결합검사) |
| H | 가입.번호 | 전 항목 매칭 키 |
| **+** | **서비스번호8** | **1차에서 미리 추출** |
| **+** | **원스톱키(앞4+뒤4)** | K-5 — **1차에서 미리 추출** |
| L | 개통상태 | K-2 |
| AB | 접점코드 | K-3 |
| AE | 주민번호 | K-4 |
| **+** | **생년월일6** | K-4 — **1차에서 미리 추출** |
| AG | 명의자 연락처 | K-2/K-3 복합키 |
| **+** | **전화앞5** | **1차에서 미리 추출** |
| BK | 사업자번호 | K-4 (법인 결합) |
| **+** | **1차판정** | 1차에서 걸러진 결과 (결합후보/오류 사유) |

**포인트: 매칭 키를 1차에서 미리 만들어서 열로 넣어줍니다.**
그러면 2차 VBA는 문자열 파싱을 안 해도 되고, 코드가 훨씬 짧고 빨라집니다.
(01 문서의 B-2 "마지막 4자리 폴백" 같은 위험한 코드가 통째로 사라집니다)

### 3-2. 시트 구성

| 시트 | 내용 |
|---|---|
| `웹` | 위 정리된 열 + 1차 판정 결과 |
| `접수` | KOS 접수리스트 양식 (붙여넣기용, 헤더만) |
| `결합` | KOS 결합리스트 양식 (붙여넣기용, 헤더만) |
| **`원스톱`** | **KOS 원스톱 양식 (신규, 붙여넣기용)** |
| `결과` | 2차 매크로 결과 — **사유 텍스트로** 출력 (색칠 대신) |

## 4. 반드시 고쳐야 할 것 (우선순위)

| 순위 | 항목 | 왜 |
|---|---|---|
| 1 | **셋트유형(G) 반영** | 단독 49건이 전부 `결합누락` 오탐. 검수 결과를 못 믿는 제일 큰 원인 |
| 2 | **웹 시트 헤더 1칸 밀림 수정** | 사업자번호(BL) 결합 매칭이 죽어있음 |
| 3 | **상품 정규화 재작성** | 280건 중 36건(12.9%)이 틀림. `TV에센스` 누락 + `패밀리` 삭제 + `ElseIf` 미사용 |
| 4 | **`마지막 4자리` 폴백 제거** | 전화번호 끝자리로 엉뚱한 고객과 매칭 |
| 5 | **결합 키 강화** | 생년월일 6자리 단독 → 동명이인 충돌 |
| 6 | **결과를 색 대신 사유 텍스트로** | 지금은 왜 틀렸는지 안 남고 필터도 안 됨 |
| 7 | **원스톱 검수 신규 추가** | 아예 없음 |
| 8 | **상부점 매핑 테이블화** | 6건 오탐 |
