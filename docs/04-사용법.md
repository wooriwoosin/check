# 04. 사용법

## 전체 흐름

```
① 웹 어드민에서 전체고객상품 다운로드
        ↓
② 1차 웹 검수 (브라우저)  ← 이 도구
   · KT전산 이관 대상만 필터링 (979 → 274)
   · 결합대상 감지, 개통기한·상부점·판매점·OSS·상품매핑·가입번호 점검
   · 제외 데이터를 뺀 이관 파일(.xlsx) 생성
        ↓
③ 이관 파일을 KT전산(VPN)으로 반입
        ↓
④ KOS 데이터 3종을 붙여넣기 → 2차 검수 자동 계산
```

---

## 1차 웹 검수 (브라우저)

주소를 열고 **`전체고객상품리스트_YYYYMMDD_HHMM.xlsx`** 를 끌어다 놓으면 끝입니다.

이 파일에는 `접점코드` 와 `고객이력` 이 **둘 다 들어있어서 파일 하나면 됩니다.**
해피콜 목록을 따로 올릴 필요가 없습니다.

### 받을 수 있는 형식

| 형식 | 설명 |
|---|---|
| **`.xlsx`** | 지금 형식. 진짜 엑셀 파일. **고객이력 포함** → 파일 하나로 전부 검수 |
| `.xls` | 예전 형식. 확장자만 xls 이고 실제로는 HTML 표. 고객이력이 없어 해피콜 목록을 따로 올려야 함 |
| 해피콜 목록 | 접점코드가 없어 상부점 검수와 이관 파일 생성만 빠짐 |

형식은 **자동으로 알아봅니다.** 그냥 올리시면 됩니다.

### 파일별로 되는 검수

| | `.xlsx` (지금) | 예전 `.xls` | 해피콜 목록만 |
|---|---|---|---|
| 결합 · 개통기한 · 판매점 · OSS · 상품매핑 · 가입번호 | ✅ | ✅ | ✅ |
| **상품권** | ✅ | 해피콜 목록을 같이 올려야 | ✅ |
| **상부점** | ✅ | ✅ | ❌ `접점코드` 없음 |
| **KT전산 이관 파일 생성** | ✅ | ✅ | ❌ `접점코드`·`사업자번호` 없음 |

해피콜 목록만 올리면 화면에 안내가 뜨고 다운로드 버튼이 잠깁니다.
자세한 차이는 [06-로우데이터-2종-비교.md](06-로우데이터-2종-비교.md) 참고.

> 파일은 **브라우저 안에서만** 처리됩니다. 서버로 올라가지 않고, 인터넷 연결도 필요 없습니다.
> (페이지를 한 번 연 뒤에는 오프라인에서도 동작합니다)

### 화면 구성

| 카드 | 뜻 |
|---|---|
| 전체 행 | 받은 파일의 전체 행 수 |
| KT전산 이관 대상 | 필터를 통과해서 넘어갈 건 |
| 이관 제외 | 타 통신사 / 업셀링·약정갱신 / 대성 상부점 |
| **결합대상 (고객)** | **전산 넘기기 전에 결합을 걸어줘야 하는 고객** |
| 결합 확인필요 (고객) | 사람이 한 번 봐야 하는 건 |
| 1차 검수 지적 | 개통기한·상부점·판매점·OSS·상품매핑·가입번호 |

각 탭에는 **생년월일**(주민번호 앞 6자리)이 같이 나옵니다.
KOS 결합리스트의 생년월일과 같은 형태라 눈으로 대조하기 좋습니다.

### 탭별 점검 항목

| 탭 | 무엇을 보나 |
|---|---|
| **결합대상** | 기존 KT 휴대폰(유형1) 또는 기존 KT 일반·인터넷전화(유형2) 결합 요청<br>※ **동판·유심동판은 제외** (유선 개통 후 무선 진행 → 결합이라 별개 건) |
| 결합 확인필요 | 근거가 약하거나 유형이 안 갈리는 건 |
| 개통기한 | 개통기한 ≠ 접수일의 익월 말일 |
| 상부점 | ① 상부점이 온라인 ↔ 접점코드도 온라인<br>② 상품명이 `유선기타_*` ↔ 상부점도 `유선기타`<br>③ 접점코드가 `(KT)도매`(우리 직영) → 상부점에 `도매`<br>※ 업체 접점(엠제이통신·다성통신 등)은 각자 상부점이 달라 1차에서 안 봅니다.<br>실제 접점 대조는 **2차**에서 KOS 접점명으로 합니다 |
| 판매점 접수경로 | 협력점명 `☆★` → 접수경로 협력점 / `□■` → 판매점. 안 맞는 건 |
| **OSS(원스톱전환)** | **웹 원스톱해지 라인 전체 + 원스톱키. KOS 원스톱과 수량 대사용** |
| 상품 매핑 | 상품옵션을 KT 상품명으로 못 바꾸는 건 |
| 가입번호 | 상품별로 형식이 맞는지 (아래 표) |
| **KT 상품권 미등록** | 본인인증이 **KT 직영**인데 상품권이 `등록예정` 인 건 — 바로 등록 가능<br>※ **해피콜 목록을 올려야 검사됩니다** |
| **상품권 메모누락** | 인증이 필요한 고객(타사·**KT알뜰폰**)이 `등록예정` 인데 `★상품권` 메모가 없는 건<br>※ **해피콜 목록을 올려야 검사됩니다** |

> **결합 · 판매점 접수경로 · 가입번호 · 상품권** 은 개통상태가
> **`접수완료`·`실적확인중`·`개통완료`** 인 건만 봅니다 (취소·보류 제외).

### 가입.번호 형식

| 상품 | 있어야 하는 것 |
|---|---|
| 인터넷 · TV | **`z!` 서비스번호 11자리 + 전화번호** 둘 다<br>예: `z!62254918905 / 031-066-3798` |
| 일반전화 · 인터넷전화 | **전화번호만** 있어도 됨<br>예: `031-759-0101` · `02-2043-9969` · `070-8888-9965` |
| 버디AX · 복수AP | **`9999` 로 시작하는 12자리**<br>예: `999903829122` |

완전히 비어 있으면 어느 상품이든 오류입니다.
| 이관 제외 | 왜 빠졌는지 사유별로 |

> **결합대상은 전산에 넘기기 전에 처리하세요.**
> 전산은 셋트유형이 단독이면 무조건 `결합 X` 로 잡아서, 여기서 못 걸면 놓칩니다.

## 2차 KT전산 검수 (엑셀)

`이관 파일 다운로드` 로 받은 **`KT검수_이관_YYMMDDHHMM.xlsx`** 를 KT전산으로 가져갑니다.

**파일을 열면 `할일` 시트가 먼저 나옵니다. 거기만 보시면 됩니다.**

### ① 붙여넣기

| 시트 | 붙여넣을 자료 | 위치 |
|---|---|---|
| `접수` | KOS 접수리스트 | **3행 A열부터** |
| `결합` | KOS 결합 리스트 | **3행 A열부터** |
| `원스톱` | KOS 원스톱 | **2행 A열부터** |

붙여넣는 순간 전부 자동 계산됩니다. **매크로 실행 버튼이 없습니다.**

> ⚠️ 각 시트 오른쪽 끝의 **보조열은 지우지 마세요.** 매칭 키를 만드는 수식입니다.
> · `접수` AV~AZ  · `결합` U  · `원스톱` Q~R

### ② 붙여넣기가 제대로 됐는지 먼저 확인

`할일` 시트 맨 위에 **매칭률**이 나옵니다.

```
KOS 접수리스트 붙여넣은 행     6 건
웹 224건 중 접수 매칭된 건    185 건
매칭률                      83%
```

**매칭률이 0% 거나 매우 낮으면 붙여넣기가 잘못된 것입니다.** 이때 확인할 것:

- 접수리스트를 **3행부터** 붙여넣었나요? (1·2행은 머리글)
- **A열부터** 붙여넣었나요? 열이 밀리면 전부 안 맞습니다
- 보조열(회색 머리글)을 지우지 않았나요?
- 붙여넣은 행이 2,000행을 넘었나요? 넘으면 보조열 수식을 아래로 끌어 채우세요

숫자를 보기 전에 **여기부터** 확인하시면 헛수고를 피합니다.

### ③ 확인할 항목 — 위에서부터 순서대로

`할일` 시트에 8개 항목이 건수와 함께 나옵니다. **0이면 넘어가면 됩니다.**

| # | 항목 | 어디서 보나 | 무엇을 하나 |
|---|---|---|---|
| 1 | 접수없음 | 웹 시트 `[접수검수]` 필터 | KT전산에 접수가 안 된 건 — 접수 |
| 2 | 상품상이 | 웹 시트 `[접수검수]` 필터 | 접수는 됐는데 상품이 다름 |
| 3 | 결합누락 | 웹 시트 `[2차오류사유]` 필터 | 1차 결합대상인데 전산에 결합 없음 |
| 4 | 개통상태 불일치 | 웹 시트 `[개통상태검수]` 필터 | 웹 개통상태 ↔ KOS 진행상태 |
| 5 | 업체 상이 | 웹 시트 `[업체검수]` 필터 | 웹 접점코드 ↔ KOS 접점명 |
| 6 | 원스톱 미접수 | `OSS대사` 시트 | 웹엔 OSS 라인이 있는데 KOS 에 없음 |
| 7 | 웹미존재 접수건 | `접수` 시트 `[웹 매칭여부]` 필터 | KOS 에만 있는 접수건 |
| 8 | OSS 수량 차이 | `OSS대사` 시트 | 웹 OSS 라인 수 ↔ KOS 원스톱 행 수 |

### ④ 대사 대상이 아닌 건은 알아서 빠집니다

전체를 다 볼 필요가 없습니다. 아래는 **오류가 아니라** 대사 자체가 안 되는 건이라
`2차오류사유` 에 안 잡힙니다.

| 표시 | 뜻 | 8-27 기준 |
|---|---|---|
| `대사제외` | 취소·보류 건 — 전산에 접수 자체가 없음 | 26건 |
| `OSS별도` | 원스톱해지 라인 — `OSS대사` 시트에서 확인 | 9건 |
| `대사불가(전화)` | 일반전화·인터넷전화 — `z!` 서비스번호가 없어 매칭 불가 | 4건 |

**224건 중 실제로 KOS 와 대사하는 건 185건**입니다.

### ⑤ 웹 시트 보는 법

열 순서가 **보는 순서**입니다.

```
A~G   누구인지        No · 고객명 · 생년월일 · 상품명 · 상품옵션 · 셋트유형 · 개통상태
H~Q   판정 ← 여기만   2차판정 · 2차오류사유 · 접수검수 · 접수상태 · 개통상태검수 ·
                     업체검수 · 결합검수 · 원스톱상태 · 1차판정 · 상품권
R~AC  대조용 원본     가입.번호 · 접점코드 · 접수접점명 · 상부점 · …
AD~AI 매칭 키         (숨김 — 볼 필요 없음)
```

- **`[2차판정]` 을 `확인필요` 로 필터링**하면 볼 것만 남습니다
- `[2차오류사유]` 에 무엇이 걸렸는지 글자로 적힙니다
- 판정 열은 전부 수식입니다. 값을 직접 고치지 마세요

### 붙여넣었는데 숫자가 안 바뀔 때

**이 파일에는 매크로가 없습니다. 실행할 버튼이 없는 게 정상입니다.** 수식이라 붙여넣으면 바로 계산됩니다.
그래도 안 바뀌면 순서대로 확인하세요.

| | 확인 |
|---|---|
| 1 | 위에 **보호된 보기** 띠가 떠 있으면 **[편집 사용]** 을 누르세요 (이 상태에선 계산이 멈춥니다) |
| 2 | 숫자 대신 `=IF(...` **글자가 그대로 보이면** — <kbd>Ctrl</kbd> + <kbd>`</kbd> (숫자 1 왼쪽 키) |
| 3 | **파일 > 옵션 > 수식 > 계산 옵션** 이 **자동** 인지 |
| 4 | 그래도 안 되면 <kbd>F9</kbd> 또는 <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>F9</kbd> 로 강제 재계산 |

같은 안내가 `할일` 시트 아래쪽에도 적혀 있습니다.

## 부가상품 KOS 매핑

`KT_부가상품` 은 KOS 에서 상품명이 갈립니다. 현재 매핑은 이렇습니다.

| 웹 상품옵션 | KOS 상품구분 | KOS 상품군 | KOS 상품명 |
|---|---|---|---|
| `복수AP` | 홈IoT | 복수AP | **WiFi패키지 플러스** |
| `100M+버디AX` `500+버디AX` `1G↑+버디AX` | 홈IoT | 복수AP | **GiGA WiFi Buddy ax** |
| `원스톱해지(OSS)` | — | — | 접수리스트 아님 → `OSS대사` 시트로 확인 |

**상품군은 둘 다 `복수AP` 로 같고 상품명이 갈리므로, 상품명 기준으로 맞춥니다.**

목록에 없는 부가상품이 나오면 속도(`500M` 등)만 보고 인터넷 상품으로 오인하지 않도록
빈값 처리해서 1차 `상품 매핑` 탭에 뜨게 합니다. 그때 `assets/rules.js` 의 `ADDON_MAP` 에 한 줄 추가하면 됩니다.
