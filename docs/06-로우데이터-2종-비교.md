# 06. 로우데이터 2종 비교 — 대체 가능한가?

**결론: 대체 불가. 두 파일 다 필요합니다.**
해피콜 목록에는 **`접점코드`가 없어서** 상부점 검수와 2차 업체 대조를 할 수 없습니다.

---

## 1. 같은 데이터인가

같은 8-19 접수분이고 내용은 사실상 동일합니다.

| | 전체고객상품 (16:18) | 해피콜 전체고객상품목록 (16:44) |
|---|---|---|
| 행 수 | 804 | 805 |
| 열 수 | **63** | **57** |

행 차이 1건은 `전홍진/ㄱ△/동판 · 모바일_SKT` — 두 파일을 뽑은 26분 사이에 들어온 건입니다.
그 1건 말고는 **804건이 완전히 일치**합니다.

---

## 2. 열 차이

### 해피콜에만 있는 열 (3개)

| 열 | 쓸모 |
|---|---|
| **`고객이력`** | ⭐ **상품권 메모 검수(W-10)에 필요** |
| `정책지역` | (기본의 `정책구분` 자리) |
| `우편번호` | |

### 기본에만 있는 열 (9개)

| 열 | 어디에 쓰나 |
|---|---|
| **`접점코드`** | ⭐ **상부점 검수(W-4)** + **2차 업체 대조(M2-1)** |
| **`사업자번호`** | ⭐ 법인 결합 매칭 |
| `정책구분` | |
| `물류수령(주소)` / `사은품주민번호` / `이메일` / `인입최초시간` / `취소요청일` / `단말기명` | 현재 검수엔 미사용 |

**`접점코드`와 `사업자번호`가 없어서 해피콜 목록만으로는 검수가 안 됩니다.**

---

## 3. ⚠️ `No` 열은 조인 키로 쓸 수 없습니다

두 파일 모두 `No` 가 1부터 붙어 있지만 **정렬 순서가 서로 다릅니다.**

```
No=1   기본  = 서영진/♠ / 단판
       해피콜 = 이준기/가족/단판 / 가족동판(UIT)
```

804건 중 `No` 로 조인하면 **71건만 우연히 맞습니다(8.8%)**.

→ **주민번호 기반 고객키로 조인합니다.** 고객이력은 어차피 고객 단위 기록입니다.

| 조인 방식 | 결과 |
|---|---|
| `No` | 71 / 804 ❌ |
| **주민번호 고객키** | **398 / 398 ✅** |

---

## 4. 두 파일의 `가입.번호`가 다를 수 있습니다

export 시각이 다르면 그 사이의 수정이 반영됩니다. 이번 데이터에서는 **1명**이 달랐습니다.

```
허원/긴급/(모)
  기본  (16:18) : (★상품권)z!6225428059 / 02-1765-2419
  해피콜(16:44) :          z!6225428059 / 02-1765-2419
```

**검수는 기본 파일의 `가입.번호` 를 기준으로 합니다.** KT전산으로 넘어가는 게 기본 파일이기 때문입니다.

> 두 파일은 **되도록 비슷한 시각에** 받아주세요.

---

## 5. 그래서 도구는 이렇게 동작합니다

```
① 전체고객상품.xls        → 필수. 모든 검수의 기준
② 해피콜 전체고객상품목록.xls → 선택. 올리면 '상품권 메모' 검수가 추가됨
```

해피콜 파일에서는 **`고객이력` 만** 가져오고, 나머지는 전부 기본 파일을 씁니다.

---

## 6. W-10 상품권 메모 검수

### 왜 필요한가

휴대폰이 KT 가 아니면 상품권 본인인증이 안 돼서 **나중에 등록**합니다.
그래서 `가입.번호` 에 `(★상품권,문자)` 같은 메모를 남겨두는데, **가끔 빠뜨립니다.**

### 판정

| 고객이력 `ㅇ상품권:` 값 | 상태 |
|---|---|
| `등록예정` `등록 예정` `예정` `일괄등록예정` `추후등록` `(빈값)` | **예정** → `★상품권` 메모가 있어야 함 |
| `모이6` `모농7` `신세계1` `스카이 쿠폰4만원` … | **등록** (실제 상품권명) → 검사 안 함 |

`가입.번호` 의 메모 형태: `(★상품권,문자)` 38 · `(★상품권)` 14 · `(★상품권,이메일)` 1

**메모는 고객 단위**로 남기므로, 같은 고객의 **어느 라인에든** 있으면 통과입니다.
