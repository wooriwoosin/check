# 06. 로우데이터 2종 비교 — 대체 가능한가?

**결론: 대체 불가. 두 파일 다 필요합니다.**
해피콜 목록에는 **`접점코드`가 없어서** 상부점 검수와 2차 업체 대조를 할 수 없습니다.

---

## 1. 같은 데이터인가

같은 8-19 접수분이고 내용은 사실상 동일합니다.

| | 전체고객상품 (16:18) | 해피콜 전체고객상품목록 (16:44) |
|---|---|---|
| 행 수 | 804 | 805 |
| 열 수 | **63** | **57** |

행 차이 1건은 `전홍진/ㄱ△/동판 · 모바일_SKT` — 두 파일을 뽑은 26분 사이에 들어온 건입니다.
그 1건 말고는 **804건이 완전히 일치**합니다.

---

## 2. 열 차이

### 해피콜에만 있는 열 (3개)

| 열 | 쓸모 |
|---|---|
| **`고객이력`** | ⭐ **상품권 메모 검수(W-10)에 필요** |
| `정책지역` | (기본의 `정책구분` 자리) |
| `우편번호` | |

### 기본에만 있는 열 (9개)

| 열 | 어디에 쓰나 |
|---|---|
| **`접점코드`** | ⭐ **상부점 검수(W-4)** + **2차 업체 대조(M2-1)** |
| **`사업자번호`** | ⭐ 법인 결합 매칭 |
| `정책구분` | |
| `물류수령(주소)` / `사은품주민번호` / `이메일` / `인입최초시간` / `취소요청일` / `단말기명` | 현재 검수엔 미사용 |

**`접점코드`와 `사업자번호`가 없어서 해피콜 목록만으로는 검수가 안 됩니다.**

---

## 3. ⚠️ `No` 열은 조인 키로 쓸 수 없습니다

두 파일 모두 `No` 가 1부터 붙어 있지만 **정렬 순서가 서로 다릅니다.**

```
No=1   기본  = 서영진/♠ / 단판
       해피콜 = 이준기/가족/단판 / 가족동판(UIT)
```

804건 중 `No` 로 조인하면 **71건만 우연히 맞습니다(8.8%)**.

→ **주민번호 기반 고객키로 조인합니다.** 고객이력은 어차피 고객 단위 기록입니다.

| 조인 방식 | 결과 |
|---|---|
| `No` | 71 / 804 ❌ |
| **주민번호 고객키** | **398 / 398 ✅** |

---

## 4. 두 파일의 `가입.번호`가 다를 수 있습니다

export 시각이 다르면 그 사이의 수정이 반영됩니다. 이번 데이터에서는 **1명**이 달랐습니다.

```
허원/긴급/(모)
  기본  (16:18) : (★상품권)z!6225428059 / 02-1765-2419
  해피콜(16:44) :          z!6225428059 / 02-1765-2419
```

**검수는 기본 파일의 `가입.번호` 를 기준으로 합니다.** KT전산으로 넘어가는 게 기본 파일이기 때문입니다.

> 두 파일은 **되도록 비슷한 시각에** 받아주세요.

---

## 5. 그래서 도구는 이렇게 동작합니다

```
① 전체고객상품.xls        → 모든 검수의 기준
② 해피콜 전체고객상품목록.xls → 선택. 올리면 '상품권' 검수가 추가됨
```

해피콜 파일에서는 **`고객이력` 만** 가져오고, 나머지는 전부 기본 파일을 씁니다.

### 해피콜 목록만 올려도 됩니다

지난 달 접수분 상품권만 보고 싶을 때처럼, 해피콜 목록을 **첫 번째 칸에 그냥 올려도** 됩니다.
`접점코드` 가 없다는 걸 감지해서 **상부점 검수와 이관 파일 생성만 빼고** 나머지는 그대로 돌아갑니다.

---

## 6. W-10 상품권 검수

### 6-1. 두 가지를 봅니다

| | 대상 | 왜 |
|---|---|---|
| **KT 상품권 미등록** | 본인인증이 **KT 직영**인데 상품권이 `등록예정` | KT 직영은 인증 없이 **바로 등록**할 수 있어서 접수자가 등록하는 게 정석 |
| **상품권 메모누락** | **인증이 필요한 고객**이 `등록예정` 인데 `가입.번호` 에 `★상품권` 메모가 없음 | 나중에 등록해야 하는데 표시를 빠뜨림 |

> ⚠️ **KT망 알뜰폰(`KT알뜰`·`KT알뜰폰`)은 인증이 필요합니다.**
> `KT` 글자가 들어가지만 **바로 등록이 안 되므로** 타사와 같이 "메모누락" 쪽에서 봅니다.
> (`SKT` 안에도 `KT` 가 들어있어서, 타사 → 알뜰 → KT 순으로 걸러야 합니다)

`★상품권` 메모 형태: `(★상품권,문자)` · `(★상품권)` · `(★상품권,이메일)`

### 6-2. ⭐ 판정은 "가장 최근 상품권 신호" 기준입니다

고객이력은 **최신이 위**에 쌓입니다. 그리고 **등록을 마치면 `ㅇ상품권` 항목을 고치는 게 아니라,
그보다 나중 시각에 상품권 코드 메모를 따로 남깁니다.**

```
안선희  :고객메모:농지6                    (2026-08-20 16:15)   ← 최신. 등록 완료
서영민  :고객메모:… ㅇ상품권 : 등록예정 …    (2026-08-19 13:56)
```

**값만 보면 "등록예정" 이라 오탐이 납니다.** 그래서 두 종류의 신호를 모아 **시각이 가장 늦은 것**으로 판정합니다.

| 신호 | 예시 | 상태 |
|---|---|---|
| `ㅇ상품권 :` 항목값 | `등록예정` `등록 예정` `예정` `일괄등록예정` `(빈값)` | **예정** |
| `ㅇ상품권 :` 항목값 | `모이4` `신세계1` `스카이 쿠폰4만원` | **등록** |
| **상품권 코드 단독 메모** | `모이3` `모다3` `모농6` `농지6` `농지10` `로못4` `문자+모이10` | **등록** |

코드 메모는 `부재2` `해피콜부재2차` `ㅂㅈ1 0956` 같은 메모와 섞이지 않게
**브랜드 글자(모·이·농·지·신·롯·로·다·스)로 시작하는 것만** 인정합니다.

### 6-3. 취소·보류 건은 검수하지 않습니다

개통상태가 **`접수완료` · `실적확인중` · `개통완료`** 인 라인만 봅니다.
취소·보류 건은 상품권을 볼 이유가 없습니다.

> 실제로 우경은·김진환은 유선 라인이 **전부 취소완료** 라 대상에서 빠집니다.

### 6-4. 메모는 고객당 한 곳만 있으면 됩니다

`★상품권` 메모는 보통 **`인터넷` 라인**의 `가입.번호` 에 남깁니다.
그래서 `인터넷+TV` 든 `인터넷+전화` 든 **같은 고객의 어느 한 라인에만 있으면 통과**입니다.
표기 여부는 **이관 제외된 라인(모바일 등)까지 포함해** 그 고객의 전체 행에서 확인합니다.

화면에는 **그 고객의 가입 라인이 전부** 나오므로 정말 어디에도 없는지 바로 확인할 수 있습니다.

```
252  김진환/OSS   상품권: 등록 예정 (2026-08-19 18:12)   · 부가상품  z!62254560704/041-066-0886
                                                      · TV      z!62254560704/041-066-0886
                                                      · 인터넷    z!62254560704/041-066-0886
```

### 6-5. 8-19 실측 (이관 172건)

| | 건수 |
|---|---|
| **KT 상품권 미등록** | **2명** |
| **상품권 메모누락** | **0명** |

| 구분 | 행 | 고객명 | 인증 | 최근 이력 |
|---|---|---|---|---|
| KT 미등록 | 75 | 하헌덕/동판 | KT | `예정` (19:01) |
| KT 미등록 | 621 | 권영일/2 | kt | `등록예정` (12:09) |

(메모누락은 이번 데이터에 없습니다 — 우경은·김진환은 유선 라인이 전부 취소완료라 제외)

**등록을 마친 건은 자동으로 빠집니다** — 장석빈(`모이3`) · 조영준(`모다3`) · 황선익(`농지6`).

이관 파일 `웹` 시트의 **`상품권`** 열에도 `등록` / `예정` / `KT미등록` / `메모누락` 으로 남습니다.

## 7. 구현하면서 걸린 함정 2개

### 통신사 판정 순서가 중요합니다

`고객인증(값)` 은 `SKT` `KT알뜰폰` `LG알뜰` 처럼 섞여 들어옵니다.

| 값 | 순진하게 `KT` 를 찾으면 | 실제 |
|---|---|---|
| `SKT` | ❌ KT 로 잡힘 (**S-KT**) | 타사 |
| `KT알뜰` | ❌ KT 직영으로 잡힘 | 인증 필요 |

**타사(SK·LG·U+) → 알뜰 → KT** 순서로 걸러야 합니다.

### 고객이력의 줄바꿈이 브라우저와 다르게 들어옵니다

`작성자 / :유형:내용 (일시)` 구조인데, 원본 HTML 에 따라 작성자와 유형 사이 개행이
**살아있기도 하고 아니기도** 합니다.

```
파이썬 파서 : 정다인\n:고객메모:모이3 (2026-08-19 11:45)
브라우저     : 정다인:고객메모:모이3 (2026-08-19 11:45)     ← 개행 없음
```

개행에 기대면 브라우저에서만 파싱이 깨집니다. **개행이 아니라 `:유형:` 패턴으로** 자릅니다.
